# 補足:

## 用語

| 用語 | 意味 |
| --- | --- |
| ドキュメント | 1件のレコード。JSON 1個が 1件 |
| インデックス | 同じ種類のドキュメントをまとめた箱。テーブルに近い |
| シャード | インデックスをノードに載せる単位。中にドキュメントが多数入る |
| プライマリ | 書き込みを受ける本体のシャード |
| レプリカ | 別ノードに置いたシャードのコピー |

シャードはレコードそのものではない。複数件のレコードが入ったインデックスを、ノードへ割り付けるときの単位がシャード

## ノードごとにストレージを分ける理由

各ノードは、自分に割り当てられたシャードだけを自分の volume（`es01-data` など）に書く。3台が同じ全量をそれぞれ持っているわけではない。

本体とコピーを別のディスクに置くので、1台が止まってももう1台にデータが残る。止まったノードのレプリカは本体へ昇格し、空いているノードへ新しいコピーが作られる。コンテナを消しても、volume に書いたシャードは残る。

## シャードの保管・配置方法

インデックスを作った時点で、マスターが置き場所を決める。初期設定では次のようになる。

- データ本体 (=オリジナル) はどれか1台に保存
- コピーは、本体とは別の1台に保存
- 残りの1台は、そのインデックスを持たない

どの台が本体になるかは、各ノードのシャード数がそろうようにマスターが選ぶ。書き込みのたびに入れ替わるわけではない。決めた配置は3台すべてに配られ、ノードが落ちるまでそのディスクに置き続ける。

## マスターの選定方法

`cluster.initial_master_nodes` は es01、es02、es03 の3台。どれもマスター候補で、起動時に1台がマスターになる。

## 書き込みの流れ

1. curl や Kibana は es01 の 9200 番へ届ける
2. es01 は配置を見て、プライマリのあるノードへ転送する。プライマリは es01 とは限らない
3. プライマリを持つノードが自分の volume に書き、レプリカのノードへコピーする
4. 文書そのものはマスターを経由しない。マスターが配るのは保存先の設定のみ
